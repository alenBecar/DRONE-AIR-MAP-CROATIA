# Air Map Croatia

**„Letim tu?"** — *"Can I fly here?"*

An interactive map of Croatia for drone pilots. Click any spot on the map, pick an hour, and get a quick assessment of airspace, obstacles and weather for that place and time.

<!-- ![Air Map Croatia](docs/screenshot.png) -->

> [!WARNING]
> **For information only.** Air Map Croatia does not replace the official AIP, NOTAMs or an AMC flight approval. Always check the official sources and get the required approvals before you fly. Not for navigation.

## Features

For any point on the map and any hour up to 72 hours ahead, the app combines three layers.

**Airspace**
- CTR, ATZ, TMA, RMZ, prohibited (P), restricted (R) and danger (D) areas, TRA and TSA
- Active reservations and NOTAMs from CroControl's AMC portal
- Gliding and paragliding areas

**Terrain and obstacles**
- Power lines, railways, cable cars, wind turbines and antennas
- Military sites, prisons and power plants
- National parks, nature parks and settlements

**Weather**
- Wind at 10, 80 and 120 m, plus gusts
- Precipitation and visibility
- Kp index (geomagnetic activity, which affects GNSS reliability)
- Twilight times

## Quick start

```bash
docker build -t air-map-croatia .
docker run -p 8080:80 -v airmap-data:/data air-map-croatia
```

Then open <http://localhost:8080>.

### First run

On first start the container collects all the data by itself:

- airspace zones and weather are ready in about a minute;
- the basemap and OSM obstacles take roughly 5–15 minutes.

Until the basemap has finished downloading, the page shows a notice.

## How it works

A Python pipeline fetches and processes the data in the background. The page itself is static and loads the generated files.

| Component | Source → output | Refresh |
|---|---|---|
| Web page | `web/app.html` + `web/css/app.css` + `web/js/*.js` → `tools/build_page.py server` → `web/index.html` | at build time |
| Basemap (Protomaps, OSM) | `pipeline/basemap.py` → `/data/pub/hr.pmtiles`, served with HTTP range requests | every 30 days |
| Zones, reservations, NOTAMs | `pipeline/ofm.py` + `pipeline/amc.py` → `zones.geojson`, `notams.geojson` | every 30 min (open flightmaps every 24 h) |
| Obstacles and places (OSM via Overpass) | `pipeline/osm.py` → `power`, `rail`, `aero`, `points`, `sensitive`, `protected`, `places` | every 7 days |
| Forecast (Open-Meteo, 0.25° grid) | `pipeline/wx.py` → `wx.json` | hourly |
| Kp index (NOAA SWPC) | `pipeline/kp.py` → `kp.json` | hourly |
| Satellite imagery (Sentinel-2 cloudless 2024, EOX) | nginx proxy at `/sat/{z}/{y}/{x}.jpg`, cached on disk in `/data/cache/sat` | cached permanently |

`pipeline/scheduler.py` runs these jobs in the background and records their state in `/data/pub/status.json`. An open page reloads zones, NOTAMs, the forecast and the Kp index every 10 minutes.

## AMC rules applied

The assessment follows CroControl's AMC rules for automatic approval of drone flights:

- **Inside a CTR:** automatic approval through AMC Portal Mobile from the ground up to 50 m AGL, outside the URG area.
- **URG area around the runway (2.7 NM):** no automatic approval. Flights only in exceptional cases, on special request.
- **Outside a CTR:** automatic approval up to 120 m AGL, provided no P, R, TRA, TSA or URG zone is active.
- **Uncontrolled aerodromes:** within 3 km of the runway and up to 1,000 ft AGL, flights only with the aerodrome operator's approval.

AMC does not publish URG polygons, so the app approximates the URG area as a 2.7 NM radius around the nearest runway within the CTR.

These rules reflect AMC procedures at the time of writing and may change. The official rules always take precedence.

## Privacy

The AMC data package (`/AMC/Package/InitialPackage`) contains more than public aeronautical data, including user accounts, other operators' drone reservations and contact details. `pipeline/amc.py` extracts only public aeronautical information: zones, zone activations stripped of all user fields, and NOTAMs. Nothing else is stored.

## claude.ai artifact build

A claude.ai artifact cannot fetch external resources, so everything ships as published files:

- **Page:** `tools/build_page.py artifact <out>`
- **Basemap:** `artifact/shard.py` splits the basemap into `.wasm` shards
- **Satellite imagery:** `artifact/sat.py`
